BUNDLED CHROMIUM vs GOOGLE CHROME — how sites can treat them differently
=========================================================================

The tool defaults to Playwright's bundled Chromium. Setting BROWSER_CHANNEL=chrome
makes it drive the Google Chrome installed on the machine instead. Same engine,
same automation API — but sites (and especially WAF / bot-protection layers) can
tell them apart in the following ways. Use this to decide which to run.

WHAT A SITE CAN SEE
-------------------

1. Client hints (Sec-CH-UA header + navigator.userAgentData)
   - Bundled Chromium announces the brand "Chromium".
   - Chrome announces "Google Chrome" (plus "Chromium").
   This is the big one: we hardcode a Chrome user-agent STRING in browser.py,
   but client hints are generated by the browser itself and are NOT overridden.
   A WAF that cross-checks "UA string says Chrome, client hints say Chromium
   only" can flag the mismatch. Ordinary sites and GTM/GA4 ignore this.

2. User-agent string
   - Both channels send our hardcoded Chrome 124 UA, so plain UA sniffing sees
     "Chrome" either way. But the pinned engine version behind it moves with
     Playwright releases, so the claimed version can drift from the real one —
     another mismatch signal for sophisticated fingerprinting, identical in
     both channels.

3. DRM and proprietary media
   - Chrome ships Widevine (DRM) and proprietary codecs (H.264/AAC).
   - Playwright's Chromium build does not ship Widevine and has reduced codec
     support. Fingerprinting scripts sometimes probe navigator.requestMediaKeySystemAccess
     or canPlayType; a "Chrome" with no Widevine looks synthetic.
   Only matters on sites running aggressive fingerprinting (streaming,
   ticketing, sneaker-drop-grade bot protection).

4. TLS / network fingerprint (JA3/JA4)
   - Effectively identical: both use the same BoringSSL stack for a given
     version. NOT a way to tell them apart, contrary to common belief.

5. Automation and headless signals
   - Identical in both channels: navigator.webdriver is masked by our init
     script, --enable-automation is stripped, and headless mode ("new"
     headless) is the same implementation. Choosing Chrome does NOT hide that
     a browser is automated — it only changes the brand/DRM/codec signals above.

WHAT IT MEANS FOR THIS TOOL
---------------------------

- GTM / GA4 / consent / dataLayer auditing: no difference. Google's tags do
  not discriminate between the two.
- browser_fetch WAF fallback (SEO + security-header audits on hardened sites):
  this is the path where the difference can bite. A Cloudflare/Akamai/
  PerimeterX-protected site may serve bundled Chromium a challenge or block
  page while letting installed Chrome through, because of signals 1 and 3.
- Symptoms that suggest switching to BROWSER_CHANNEL=chrome for a site:
  audits report 403/503 or a challenge page, "navigation failed", or content
  that differs from what you see manually in your own browser.

OPERATIONAL TRADE-OFFS
----------------------

                          Bundled Chromium            BROWSER_CHANNEL=chrome
  Install needed          none (playwright install)   Google Chrome on machine
  Version                 pinned by Playwright —      whatever Chrome is
                          deterministic, same in CI   installed — drifts with
                          and on every laptop         auto-updates
  Works in the Docker     yes (ships in base image)   no — Chrome is not in the
  image                                               Playwright base image
                                                      (would need extra layer)
  Bot-protection profile  weaker (Chromium brand,     stronger (real brand,
                          no Widevine)                Widevine present)

RECOMMENDATION
--------------
Default to bundled Chromium: deterministic, container-friendly, and sufficient
for everything except hardened sites. When a specific audit target blocks or
misbehaves, re-run with BROWSER_CHANNEL=chrome locally and compare. If most
audit targets turn out to be behind aggressive bot protection, revisit —
that would argue for making Chrome the default on laptops and adding a Chrome
layer to the Docker image.

Quick A/B for one site:
  HEADLESS=1 python run.py --url https://site.com                          # Chromium
  HEADLESS=1 BROWSER_CHANNEL=chrome python run.py --url https://site.com  # Chrome
